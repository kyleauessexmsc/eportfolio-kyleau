3.2 Advanced Hybrid Routing and Automated Failover

Leveraging my physical networking background, I translated traditional routing mechanics into hybrid cloud environments. For my individual assessment report (submitted at Unit 11), I designed a redundant 10 Gbps AWS Direct Connect topology utilizing Border Gateway Protocol (BGP). To satisfy sub-second failover requirements for capital markets, I integrated sub-second Bidirectional Forwarding Detection (BFD) paired with Scrapli/Python automation. This setup dynamically adjusts BGP Local Preference attributes (from 200 to 90) and applies AS-PATH prepending upon detecting link degradation, achieving deterministic route failover under 500 milliseconds across Transit Gateways.

4. Application to Industry: Financial Market Infrastructure

Applying cloud computing principles to real-world industrial contexts requires a nuanced understanding of domain-specific constraints, particularly within high-frequency trading (HFT) and capital markets (e.g., HKEX, CME, or global equities exchanges).

4.1 The Hybrid Reality: Balancing Determinism and Elasticity

A central insight gained across the team and individual project lifecycles is that a single public cloud model is inadequate for financial exchange infrastructure. Core order-matching engines demand physical colocation, customized kernel bypass network cards, and deterministic microsecond processing at Layers 1 and 2—performance profiles that multi-tenant public cloud hypervisors cannot guarantee. Conversely, building on-premises physical capacity for bursty post-trade processing, historical backtesting, and AI market surveillance is cost-prohibitive.

The solution lies in a strategically segmented hybrid cloud model (NIST SP 800-145). As demonstrated in the AFX design, keeping execution on-premises while piping market data feeds via Direct Connect to elastic AWS microservices (EC2 Auto Scaling Groups, Kinesis, and SageMaker) allows financial institutions to scale compute dynamically during market open/close surges while preserving deterministic matching loops.

4.2 Regulatory Governance and Data Sovereignty

In capital markets, compliance defines operational boundaries. Financial entities operating across global jurisdictions face strict data sovereignty laws, including GDPR and regional guidelines (such as Hong Kong SFC rules). Cloud adoption in this sector demands verifiable geographic boundaries. As implemented in my individual project report, using IaC guardrails to lock resource provisioning to designated geographic AWS Regions, combined with strict regional AWS KMS key policies, ensures raw transactional data cannot be replicated cross-border without authorization. Tokenization microservices paired with stateful micro-segmentation prove that public cloud infrastructure can achieve or exceed traditional on-premises security baselines.
